# Требования к карточкам (решения пользователя — не менять без запроса)

Почему так решено — в [decisions.md](decisions.md).

## Формат и направления
- Каждое слово → 2 карточки, **в обеих ответ нужно напечатать**: EN→RU и RU→EN
  (RU→EN не делается при flag `-`, термине с «…» или > 6 слов).
- В RU→EN подсказка — английское определение, где слово и однокоренные скрыты `___` (`mask`).
- Всё делается под **телефон (AnkiDroid)**; компьютер — только импорт и статистика, отдельно
  под него не дорабатывать.

- **Одно слово — одна карточка** во всей колоде. Если у термина разные значения в Maths и
  Physics — одна строка, перевод и определение на оба: `frequency | частота | how many times
  something happens; in physics — the number of waves per second`. Новый термин, который уже
  есть в другом предмете, не добавлять, а дописать значение в существующую строку.

## Строгая проверка
- Засчитывается только точное совпадение с вариантом из колоды
  (игнорируются регистр, ё/е, пунктуация, пробелы). Опечатка в 1 букву, другое окончание,
  синоним не из колоды = ошибка. **Никакой оценки человеком.**
- Не предлагать мягкую проверку, «почти верно», Трудно/Легко.

## Автоматическая оценка
- Оценка ставится по правильности: кнопка на карточке «Дальше →» → Хорошо (ease 3)
  при верном ответе, Снова (ease 1) при любом неверном. Кнопки Anki (Снова/Трудно/…) не нужны;
  на телефоне их можно скрыть в настройках AnkiDroid. На лицевой стороне на телефоне — кнопка «Проверить».
- Ответ из JS: компьютер `pycmd("easeN")`, AnkiDroid — JS API (`AnkiDroidJS`, `buttonAnswerEaseN`).

## Какие ответы засчитываются
- RU (`ru_accept` в build_deck.py): из поля «русский» берётся текст **до** `. ! : — – →`,
  **без скобок**; варианты через `, ; /` — любой из них. Пояснения писать в скобках или после точки:
  `опишите полностью (вид преобразования…)` → ответ «опишите полностью».
  Не делать основной вариант длинным; одиночное слово в скобках может стать вариантом — проверять.
- Кроме того, верно **всё поле целиком** и части вместе со скобками (`_whole_variants`).
  То же для EN: термин целиком со скобками («by (a time)»).
- EN (`en_accept`): термин с апострофом и без (`Newton's` / `Newtons`) — карточка превращает
  апостроф в пробел, и без этого «Newtons first law» был бы ошибкой.

## Чего нельзя менять
`MODEL_ID = 1730803200`, `DECK_ID_BASE`, `GUID_SALT = "v2"`, названия существующих терминов и
подколод — иначе при импорте Anki создаст дубликаты и прогресс потеряется. Менять перевод,
определение и пример можно: при повторном импорте карточка обновится, прогресс сохранится.

## Настройки колоды в Anki (целевые)
Применяются скриптом `anki_settings.py` (как — в [workflow.md](workflow.md)).
- Пресет «Maths» (подколоды 0, 1, 2), «Physics» (3, 4) и «Computer Science» (5): по 10 новых, 300 повторений,
  макс. интервал 60 дней, пиявка 5 (только метка).
- Колода-ящик «Новые слова» (отдельно от «IGCSE English»), пресет «Новые слова»: 0 новых,
  0 повторений — туда Женя пишет незнакомые слова (см. [workflow.md](workflow.md)).
- Главная «IGCSE English» («По умолчанию»): 20 новых, 300 повторений — общий потолок ≥ суммы,
  «для всех подколод» НЕ сохранять.
- Сбор новых — **«по возрастанию позиции»**; позиции записей чередуются Maths/Physics/Computer Science
  (Maths: 0 → 1 → 2; Physics: 4 Answer phrases → 3; CS: 5), обе карточки записи — одна позиция.
  Позиции ставит сама сборка (`build_deck.py`, `STREAMS` / `interleave`); `anki_settings.py`
  выравнивает по ним коллекцию.
- **Слова, которые Женя записал сам** (статус «добавлено»/«уже было» в `data/zhenya_inbox.tsv`) —
  самые первые позиции, в порядке записи, метка `zhenya`. Если Женя слово уже учит — в ночь
  обработки его повторение переносится на сегодня (`zhenya_apply.py`). Лимит прежний: 10 новых в день на предмет.
- Остальное как было: шаги 1 мин / 10 мин, FSRS (удержание 0.9), bury siblings.
